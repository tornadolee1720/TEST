# 空中光弦｜Air Strings Mobile V8

使用手機前鏡頭、Google MediaPipe Hand Landmarker、Canvas 2D、Web Audio 製作的免費互動光弦。這是獨立原創示範，不是 Sonic Deadhorse 的原始作品。

## 網站
https://tornadolee1720.github.io/TEST/?v=8

## 手機玩法
1. 用 iPhone Safari 或 Android Chrome 開啟 HTTPS 網頁，按「開啟鏡頭，開始玩」，授權相機（首次需下載 MediaPipe 模型）。
2. 將**雙手食指**放進鏡頭，兩隻食指指尖在畫面上拉出一條線。
3. **兩隻食指維持穩定 1 秒**，倒數圈完成後，這條線自動保存為固定光弦，不必再按固定按鈕。
4. 移動兩隻食指到不同位置，再穩住 1 秒，可以逐條建立其他琴弦，最多 10 條。
5. **張開手掌向右揮**：依畫面由上到下的琴弦位置依序刷響。**張開手掌向左揮**：反向由下到上依序刷響。每條線間隔約 62 毫秒，所以會有連續撥弦感。可在控制列關閉「🖐 掃弦」。
6. 除了揮掌，仍可用食指或中指**掃過、穿越**固定光弦，觸發那一條弦的專屬音高和視覺震動。
7. **握拳，往下敲擊**，就會發出鼓聲；也可用握拳向攝影機方向快速前推。畫面上方是較高的鼓音，下方是較沉的鼓音。保持拳頭不動不會一直發聲，需重新抬手再敲。可在控制列關閉「🥁 鼓聲」。
8. 拉錯時可按「撤銷上一條」，也能按「清空」重來；展示模式可點擊畫面試聽鼓聲。

## 音階
依新增順序分配：C4、D4、E4、G4、A4、C5、D5、E5、G5、A5。用 Web Audio 即時合成，不使用他人錄音。

## 技術細節
- 建弦使用兩手的食指指尖（MediaPipe landmark 8），依兩端位置建立預覽線。
- 兩隻食指若移動超出容忍範圍、追蹤停頓或雙手離開視野，1 秒倒數重新開始。
- 同一位置不會連續重複建立；須將手指移到另一位置才會建立新的琴弦。
- 弦的端點以畫面比例保存，可在視窗大小改變後重新定位；關閉／重新開啟會清除紀錄（沒有後端資料庫）。
- 音效使用 Web Audio，跨弦時觸發光線震動及粒子特效。
- 張掌判定：檢查四指末端與關節座標，至少三指伸直才進入揮掌模式（非握拳）。
- 掃弦只在新的攝影機追蹤影格上判斷：掌心在畫面左右位移超過寬度閾值、速度足夠且水平方向占主導，才觸發一次；鏡像前鏡頭依手機畫面顯示方向判斷。
- 右揮依弦中點的畫面 Y 座標由小到大演奏（上→下），左揮由大到小（下→上）；以小時間差逐一觸發音符。這是手勢決定的**整組掃弦**，不需要掌心精確穿過每條弦。
- 揮掌與食指單弦、握拳鼓聲分流：張掌時不觸發單指跨弦，握拳時不觸發掃弦；雙食指正在穩定建立新琴弦時暫停揮掌判定。
- 揮掌須有明顯的左右位移與速度，停住不會一直重播；可反方向再揮，或停頓後再次揮掌。
- 拳頭辨識：MediaPipe 指尖與指根之相對距離推估握拳（至少 3 根手指彎曲）；握拳後快速下敲、或向鏡頭前推使手掌影像變大時，觸發鼓聲。左右手可分別敲擊，有冷卻時間以避免重複發聲。由畫面上方至下方，鼓的基頻由約 240 Hz 降至 65 Hz。
- 對應音調為 Web Audio 即時合成的鼓聲，不是直接分析真實打擊深度。手機僅用單鏡頭，向前推的判定是以影像中的手掌大小變化估算；實際效果因照明與手機鏡頭而異。
- 相機影格在本機瀏覽器處理，網站本身不將相機畫面上傳；第三方 MediaPipe SDK 可能有使用／效能遙測，請參閱其聲明。
- 需要 HTTPS、鏡頭權限、jsDelivr 與 Google 模型載入。
- JavaScript 模擬測試已涵蓋第一條 1 秒固定、避免重複、建立第二條、不同音階與跨弦觸發。尚未保證所有手機的實機相容性和辨識效能。V6 另以合成座標測試開掌／握拳、下擊觸發、避免重複擊鼓、重新抬手後再擊、手部高度與鼓音關係，以及拳頭不觸發新琴弦。

## V8 手機卡頓優化（2026-11-22）
- **主要修正**：將 MediaPipe `detectForVideo()` 從網頁主執行緒移到獨立 `hand-worker.js`（CPU Worker），用 `ImageBitmap` 傳送影格，完成辨識後只回傳 21 點 × 最多兩手的座標，避免手勢辨識反覆阻塞 UI 繪製。部分瀏覽器可能不支援 Worker 路線，此時自動退回原本的主執行緒 GPU / CPU 相容模式。
- **攝影機尺寸**：理想解析度從 640×480 調降為 480×360，24 fps 上限，實際取決於裝置支援。
- **繪圖效能**：手機一般與省電模式使用 1× canvas 像素比例；一般模式每條弦兩層光暈，線段數由 30 降到 14；粒子數量降低，渲染上限自動調節約 20–25 FPS（流暢模式約 30 FPS）。
- **手勢辨識率**：背景辨識每約 100 毫秒可發一幀，且採同時僅處理一張影格的背壓控制（drop-while-busy），避免畫面延遲越積越大。真實辨識速度以手機 CPU 與瀏覽器支援為準。
- **顯示節點**：手機預設關閉節點顯示，使用者仍可切回開啟。
- **原本玩法維持**：雙食指穩定 1 秒建弦、食指／中指單弦撥奏、張掌左右掃弦、握拳打鼓與高低音映射。
- **驗證**：已檢查 JS 語法、GitHub 檔案及 HTML 控制項對應、Canvas 手機 pixel ratio、辨識間隔與核心手勢函式。Worker 的真實模型載入和手機 FPS 必須實機測試；此版本不宣稱一定達到 30 FPS。

### V8 Troubleshooting
- 開頁面後版本標示應為 `MOBILE V8`。若仍為 V7，重新整理或使用 `?v=8` 連結。
- 畫面左上角顯示「背景追蹤」代表 Worker 成功；顯示「相容追蹤」代表瀏覽器採用回退辨識模式。
- 仍感覺卡時，把「效能」切到「省電」，保持「節點」關閉；若還是無法操作，回報手機型號、使用的瀏覽器、顯示的 FPS 與「背景追蹤／相容追蹤」。
